# Qwen3.8-27B / g4090

> Archive clarification (2026-10-02): actual measured input length was 34–77 tokens; 4096 was configured capacity. The prose word-range shorthand below is historical and inaccurate; use each raw sample's `quality.words` in the public samples. Recorded code checks refer to the fenced-code extractor, and do not establish semantic correctness. Unsloth native, vLLM and SGLang remain unmeasured.

本次实测与原始文件见 [index](../assets/g4090-qwen38-benchmark-2026/index.md)；公开作者数据见 [2026-10-01-qwen38-4090-landscape](2026-10-01-qwen38-4090-landscape.md)。模型名称由官方 Hugging Face 的配置核实，不用 Qwen3.5/3.6 的速度充当 Qwen3.8 结果。

## 实测协议

GPU 3 是 RTX 4090（UUID `GPU-REDACTED`）。开始时其他用户约占 5.4 GiB；这些任务在编译/测量间自然退出或重启，逐请求快照保存在原始结果，本次没有终止或修改其他用户任务，不能称整轮为独占卡性能。driver 570.124.06 / CUDA Toolkit 12.8 / GCC 13 的独立环境，实际 mem 与利用率附在结果。短 context、单并发、temperature=0、seed=42、presence/frequency penalty=0、thinking off，JSON/code/prose 每种 3 次，warmup 不计。

实际GPU测试覆盖Cinference（jram4 NInfer）、Erik NInfer、llama.cpp、ExLlamaV3四份源码，属于三个框架家族。全部模式与请求串行运行于单张物理GPU3；没有四卡并行、tensor parallel或跨卡吞吐测试。SGLang、vLLM等检索候选未在本轮GPU运行；HyperQwen仅克隆，TabbyAPI仅CPU准备。

decode 指标为两 engine 官方兼容 timings 中的 `predicted_per_second`，均等价于 `(completion_tokens-1)/decode_seconds`；E2E output token/s 为 `completion_tokens/client_wall_seconds`。`prompt_ms` 包含首 token 的服务器计算阶段，不是客户端 streaming TTFT。本轮没有测 streaming TTFT。

每个 NInfer/Cinference 模式用全新服务进程、`--no-prefix-reuse --greedy`；llama 请求 `cache_prompt=false`，复核实际 cache counters。code 只作 AST 语法解析、无模型代码执行；JSON 只检查解析及三个 districts；prose 记录词数。HTTP 成功不表示语义或 benchmark 任务质量通过。

不同 engine 使用不同发布量化：NInfer 的 Q4/Q5 + Q8 head，llama 的 Unsloth UD-Q4_K_M，EXL3 的 4.00 bpw。因此这是同卡部署选型，无法单独归因 engine kernel 快慢。固定请求长度上限为 512 输出 token，实际数量另存，不把截断生成记为完整任务通过。

Cinference MTP7 在本轮 HTTP 的 JSON/code 上最快；散文适合较短 draft，Cinference MTP3 约100.2、Erik MTP3约101.0 token/s。本轮三次样本不足以证明这0.8 token/s差异是稳定优势。单一draft长度不能覆盖所有负载。

HTTP 的 JSON 输出都是170token，解析和三个districts检查各3/3通过。code/prose 均触及512-token上限：Python AST检查未通过，代码语义测试未执行；散文约392–395词，未完成500词目标。因此这些是受限输出长度的速度样本，不能写成完整LRU任务通过或模型质量评测。

Erik K7 启动失败，明确报 `--spec mtp requires --draft-tokens in [1,5]`；保留失败日志并改测支持的K5，不伪造K7速度。Cinference首轮使用不同的默认presence penalty，约229.8/202.9/88.2 token/s；只保留为initial diagnostic，正式表采用显式penalty=0复测，不能混合取最高值。

## EXL3 原生 MTP / DFlash2

相同GPU3、context4096、Q4 K/V、最多512输出token、三次中位数；每次fresh process + Generator，27/27请求完成，所有raw `cached_tokens=0`。下表每格为 **EXL3 native / generation-call output token/s**；后者含tokenization/prefill/decode，排除模型load/warmup，属于进程内调用速度。原生 `N/time_generate` 计入首decode，与HTTP的 `(N−1)/decode_seconds` 及HTTP墙钟时间不同，不能直接混列作engine倍率。

这个固定DFlash2量化的config实际 `block_size=8`，默认draft是K7。K15首请求因为15/7维度不符失败，保留日志；远端runner加入CPU上限检查，未修改模型config假装block16。上述观测支持选择Cinference处理本轮code/JSON；EXL3 DFlash2的含prefill调用速度也低于Cinference对应HTTP E2E速度。
