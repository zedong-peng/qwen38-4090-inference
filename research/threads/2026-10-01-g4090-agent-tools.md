# g4090 开发工具安装记录

用户要求在 `g4090` 下载 Claude Code、Codex、OpenCode 和 CC Switch。已完成普通用户目录安装和启动命令验证；没有运行模型请求。精确安装资产、脚本、软件来源和哈希见 [index](../assets/g4090-agent-tools-2026/index.md)。

## 实际交付

| 命令 | 实测版本 | `--version` | `--help` |
|---|---|---:|---:|
| `claude` | `2.1.286 (Claude Code)` | 0 | 0 |
| `codex` | `codex-cli 0.159.2` | 0 | 0 |
| `opencode` | `1.18.33` | 0 | 0 |
| `cc-switch` | `cc-switch 5.10.5` | 0 | 0 |

退出码均来自一次新的非交互 SSH 会话，四个命令均解析到 `/home/REMOTE_USER/.local/bin/`。额外安装 Node.js `v24.21.0` / npm `11.19.0`，作为官方 npm 安装方式的依赖。所有文件属于当前普通用户，无需 sudo。

CC Switch 桌面版 `3.20.4` 的官方 Linux x86_64 AppImage 已下载到：

```text
~/.local/share/g4090-agent-tools/downloads/CC-Switch-v3.20.4-Linux-x86_64.AppImage
```

别名为 `cc-switch-gui`。`--appimage-version` 退出 0，输出 runtime commit `75849dc`，这只是 AppImage runtime 检查，不能视为桌面应用启动。SSH 环境没有 DISPLAY，图形界面未启动。[官方项目明确桌面版需要 GUI，并推荐社区维护的 CC Switch CLI 用于服务器 / SSH](https://github.com/farion1231/cc-switch#faq)。`cc-switch` 是该独立 CLI；两者没有混称。

## 使用

新建 SSH 会话即可找到命令：

```bash
ssh g4090
claude --version
codex --version
opencode --version
cc-switch --version
```

已有 shell 如未刷新 PATH，执行：

```bash
source ~/.local/share/g4090-agent-tools/env.sh
```

之后 `claude`、`codex`、`opencode` 启动各自工具；`cc-switch` 启动终端交互界面，`cc-switch --help` 查看管理命令。登录 / provider 配置需使用用户自己的账号或已有凭据；本次没有写入、迁移或打印任何 API key、OAuth token、provider 配置。

## 环境与复现

远端是 Ubuntu 22.04.5 / Linux x86_64，SSH 普通用户 `zdpeng`，无免密 sudo。检查时四张 4090 均有既有任务；本次仅安装开发工具，不使用 GPU，不更新驱动，不终止既有进程。

安装根目录是 `~/.local/share/g4090-agent-tools/`；npm 使用独立 `npm/` prefix 和 `npm-cache/`。`~/.local/bin/` 下创建 launcher，已有 launcher 冲突时脚本保留并报错。`.bashrc` / `.profile` 各增加同一个有标记的 PATH 段，备份位于安装根目录的 `bashrc.before-agent-tools` / `profile.before-agent-tools`，权限 0600。

脚本固定安装 Node.js 24.21.0、Claude Code 2.1.286、Codex 0.159.2、OpenCode 1.18.33、CC Switch CLI 5.10.5、桌面版 3.20.4。可在 Linux x86_64 普通账号执行归档的 [install_agent_tools.py](../assets/g4090-agent-tools-2026/supplementary/install_agent_tools.py)，远端副本为 `~/install_agent_tools_20261001.py`。下载包通过 SHA-256 校验；npm 按 registry integrity 校验下载包，精确 package metadata 已归档。

有两项现场约束已处理：

- Claude 的原生安装地址 `https://claude.ai/install.sh` 在远端返回地区限制页面；采用 [官方支持的 npm 方式](https://code.claude.com/docs/en/setup#install-with-npm)，安装相同 native binary。安装不等同于账号服务可用性验证。
- GitHub Release 的主下载地址在远端连接超时；Mac 下载公开官方发布包并 scp，另验证了官方 Release CDN 直连可用。最终远端 AppImage SHA-256 为 `c8d66d8193fd00fd12239bd06a8c50f517badbf50d9020a4662e95e907b318ef`，CLI 包为 `feda4dca0ecf01ec90708141cc346972683c27c1097fba22235c5022143f80ed`。未来直连失败时，可先把同名校验通过的官方包放入安装根目录的 `downloads/`，再执行脚本，脚本复用正确缓存。

npm 11.19.0 会限制未允许的 install scripts；最终脚本使用一次性 `--allow-scripts=@anthropic-ai/claude-code,opencode-ai`，没有修改全局 npm 的许可设置。

本记录只证明文件下载、安装和本地命令启动可用，未测试在线模型调用，也未启动桌面 GUI。推理 engine 的 token/s 应另看本主题中的速度实验记录。
